# seaf.design 内容数据契约 v1.2

> 这份文件是网站（Claude Code）和内容流水线（Hermes）之间唯一的接口。两边都以它为准，改字段先改这里。
> v1.1 改动：**两个仓库，各有一个主人，数据单向流动。** 两边不再共用任何工作目录。
> v1.2 改动：item 新增三个可选字段 `thumb`、`figure`、`figure_unit`，其余不变。
> 日期：2026-09-07

## 0. 分工（先看这一节）

| | Claude Code | Hermes |
|---|---|---|
| 主人的仓库 | `seaf-design`（网站代码） | `seaf-content`（内容文件） |
| 本地目录 | Seaf 自定，例如 `~/dev/seaf-design` | `~/seaf-content` |
| 写什么 | `src/`、配置、`content-sample/` | `items/`、`inspiration/`、`episodes/`、`thumbs/` |
| 读什么文档 | 本契约 + `01-建站规格` | 本契约 + `02-流程改造说明` |
| **绝不做** | 进 `seaf-content`；改任何内容文件；读 02 | 进 `seaf-design`；改任何代码；读 01 |

数据流只有一个方向：Hermes 推 `seaf-content` → 网站构建时拉取 `seaf-content` → 页面。网站不写回内容仓库，Hermes 不关心网站怎么渲染。

出问题的处理：网站构建因内容文件不合契约而失败 → 构建保留上一次成功版本 → Seaf 把文件名和字段告诉 Hermes → Hermes 在自己仓库改。Claude Code 不动内容，Hermes 不动代码。

## 1. 仓库

**`seaf-content`**（Hermes 的，建议公开，内容本来就是公开的，公开就不需要构建 token）

```
seaf-content/
├── items/          资讯条目   YYYY-MM-DD-slug.md
├── inspiration/    灵感库条目 YYYY-MM-DD-slug.md
├── episodes/       集页       YYYY-MM-DD.md
├── thumbs/         灵感库缩略图 <id>.jpg
└── docs/           本契约 + 02
```

**`seaf-design`**（Claude Code 的）

```
seaf-design/
├── src/                网站代码
├── content-sample/     示例数据，结构和 seaf-content 完全一样，Claude Code 维护
├── content/            构建时 clone seaf-content 到这里，.gitignore 忽略
├── docs/               本契约 + 01
└── ...
```

网站构建时若 `content/` 不存在，用 `content-sample/`。所以 Claude Code 从头到尾不依赖 Hermes，Hermes 从头到尾不依赖网站。

## 2. 通用约定

- **id 就是文件名**（不含扩展名），不写进 frontmatter。格式 `YYYY-MM-DD-slug`，slug 是 2–4 个小写英文词，连字符连接，只用 ASCII。集页 id 就是日期 `YYYY-MM-DD`。
- 日期一律 ISO `YYYY-MM-DD`。
- frontmatter 用 YAML，正文 Markdown，正文可以为空。
- `status: draft | published`。网站只渲染 `published`，包括 RSS 和方向页。
- `direction` 只能取第 3 节的 6 个 id。网站构建时校验，非法值报错并指出文件。
- 引用其他条目一律用 id 字符串。
- 内容文件里不放任何展示层信息（颜色、图标、排序权重）。

## 3. 方向（6 个，定义在本契约，网站代码内置，内容仓库不放此文件）

| id | 名称 | 说明 |
|---|---|---|
| `tooling` | 方案与出图工具链 | AI 改了设计工序本身：平面、方案、效果图、施工图、汇报 |
| `new-space` | 新空间类型与新业务 | 空间被新需求改造：机器人工厂、数据中心、旧改、文旅、养老、展陈 |
| `industry` | 交付方式与行业结构 | 事务所的组织、岗位、收费、交付物在变 |
| `global` | 出海与远程 | 海外市场、远程接单、跨境协作 |
| `product` | 设计师做产品 | 模板资产、工具、内容、个人品牌 |
| `boundary` | AI 的边界与人的判断 | AI 做不到的事，以及经验和判断力值钱的地方 |

顺序即网站导航顺序。改名或合并：先改本契约，Claude Code 改代码，Hermes 批量替换历史文件。

## 4. 资讯条目 `items/YYYY-MM-DD-slug.md`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | date | 是 | 收录日期（不是原文发布日期） |
| `title` | string ≤60 字 | 是 | 中文标题，陈述句，不带感叹号 |
| `direction` | enum | 是 | 方向 id |
| `original` | string ≤400 字符 | 是 | **英文原句，1–2 句，从原文原样复制，含主语和限定条件。** 这是全体系最重要的字段：数字修饰什么，就在这句里 |
| `summary` | string ≤120 字 | 是 | 一句中文，只说发生了什么，不加判断 |
| `so_what` | string ≤200 字 | 是 | 对哪类设计师、哪道工序意味着什么，1–2 句 |
| `source_name` | string | 是 | 信源名 |
| `source_url` | url | 是 | 原文链接，完整 URL |
| `source_date` | date | 否 | 原文发布日期 |
| `source_type` | enum | 是 | `official` / `media` / `vendor_promo` / `social` |
| `sku` | string | 否 | 产品/型号全称，从原文原样抄 |
| `status` | enum | 是 | `draft` / `published` |
| `episode` | string | 否 | 用到这条的集页 id |
| `thumb` | string | 否 | 原文 og:image 缩略图，写 `/thumbs/<id>.jpg`；文件放 `thumbs/<id>.jpg`，宽 400px，≤40KB。抓不到就不写 |
| `figure` | string ≤6 字符 | 否 | 这条的关键数字，按原文写法：`65`、`93%`、`40`。没有明确的钩子数字就不写 |
| `figure_unit` | string ≤8 字 | 否 | 数字的单位或对象：`个工作室`、`分钟`。有 `figure` 才有它 |

`source_type` 定义：`official` 厂商/机构官方博客或新闻稿；`media` 独立媒体报道；`vendor_promo` 媒体上的赞助或推广内容（Dezeen 的 Promotion 标记一律算此类）；`social` X 等原帖。

正文：可选补充评述，通常为空。

示例：

```markdown
---
date: 2026-09-05
title: laiout 平面规划工具进入 JLL Design 旗下 65 个工作室
direction: tooling
original: "including in JLL Design's 65 global studios, where laiout was recently adopted"
summary: 商业空间平面规划工具 laiout 被 JLL Design 一家公司旗下的 65 个工作室采用，一轮 test-fit 从几天缩到平均四十分钟。
so_what: 被压缩的是排柱网、划分区、算工位这道工序，不是方案判断。做办公和商业空间的设计师值得亲手跑一次，记下它出的方案哪里需要你改。
source_name: Dezeen
source_url: https://www.dezeen.com/2026/09/03/laiout-jll-design/   # 示例路径
source_date: 2026-09-03
source_type: vendor_promo
sku: laiout
status: published
episode: 2026-09-05
thumb: /thumbs/2026-09-05-laiout-jll.jpg
figure: "65"
figure_unit: 个工作室
---
```

## 5. 灵感库条目 `inspiration/YYYY-MM-DD-slug.md`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | date | 是 | 收录日期 |
| `title` | string ≤60 字 | 是 | 项目名 |
| `studio` | string | 否 | 设计方 |
| `location` | string | 否 | 城市，国家 |
| `year` | number | 否 | 建成或发布年份 |
| `direction` | enum | 是 | 方向 id |
| `why` | string ≤120 字 | 是 | 为什么入库。"好看"不是理由 |
| `source_name` | string | 是 | |
| `source_url` | url | 是 | |
| `thumb` | string | 是 | 写 `/thumbs/<id>.jpg`；文件放在内容仓库 `thumbs/<id>.jpg`，长边 800px，≤150KB |
| `status` | enum | 是 | |

正文：可选评述，2–5 句。网站只展示缩略图、评述和外链。

## 6. 集页 `episodes/YYYY-MM-DD.md`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `date` | date | 是 | |
| `title` | string ≤24 字 | 是 | **就是抖音标题**。有数字或反差，不带感叹号 |
| `direction` | enum | 是 | 主方向（多数条目所属；`boundary` 不参与计数） |
| `items` | string[] | 是 | 本集资讯 id，按口播顺序 |
| `cta` | string ≤120 字 | 是 | 收尾承诺的那件"今天就能做的事" |
| `douyin_url` | string | 否 | 上传后补 |
| `status` | enum | 是 | |
| `checks` | object[] | 否 | 独立核验结果，每项 `{ claim, in_script, in_source, ok }` |
| `corrections` | object[] | 否 | 勘误，每项 `{ date, text }`。**只增不删** |

正文固定两节：`## 口播稿`（`[S1]` / `[S2]` 行）、`## 备注`（可选）。

示例：

```markdown
---
date: 2026-09-05
title: 六十五个工作室把平面方案交给了 AI，然后呢
direction: tooling
items:
  - 2026-09-05-laiout-jll
  - 2026-09-05-playco-greybox
  - 2026-09-05-frontiermath
cta: 挑一个你最熟的商业空间，用任何一个 AI 平面工具跑一遍 test-fit，记下它错在哪。
douyin_url: ""
status: published
checks:
  - claim: 六十五
    in_script: 全球六十五所设计事务所
    in_source: JLL Design's 65 global studios
    ok: false
corrections:
  - date: 2026-09-07
    text: 视频开场说"全球六十五所设计事务所"，原文是 JLL Design 一家公司旗下的 65 个工作室。本页已按原文更正，视频未重发。
---
## 口播稿
[S1] 先说个数字，全球六十五所设计事务所，已经把平面方案这道工序交给AI了。
[S2] 六十五所事务所？那原来画方案的那批人，现在做什么去了？
……
```

## 7. 生命周期

| 时间 | 谁 | 动作 | status |
|---|---|---|---|
| 07:00 | Hermes 扫描 | 写 items / inspiration，commit | draft |
| 09:30 | Hermes 写稿 | 写 episode，补 item 的 `episode`；派生口播稿；独立核验写 `checks`；commit | draft |
| 白天 | Seaf | 审稿（飞书，照旧） | — |
| 21:00 | Hermes 出片 | 成功后当天 draft → published，`git push` | published |
| push 后 | 自动 | GitHub webhook 触发 Cloudflare Pages 重新构建 | — |
| 发布后 | Seaf → Hermes | 「发了 <url>」→ 补 `douyin_url`，push | — |
| 任何时候 | Seaf → Hermes | 「撤 <id>」→ 改回 draft，push；「勘误 <id> ……」→ 改正文 + 追加 corrections，push | — |

## v1.3 追加：英文字段（2026-09-08，Claude Code 提议，网站已支持）

网站有中英文两套页面（`/` 与 `/en/`，页头可切换）。界面文案由网站负责；**内容字段的英文由内容文件提供**，全部可选，缺失时英文页回退显示中文。`original` 本来就是英文，不需要副本。

| 文件 | 新增可选字段 | 上限 |
|---|---|---|
| items | `title_en`、`summary_en`、`so_what_en`、`figure_unit_en` | 120 / 300 / 400 / 24 字符 |
| inspiration | `title_en`、`location_en`、`why_en` | 120 / 60 / 300 字符 |
| episodes | `title_en`、`cta_en` | 80 / 300 字符 |

正文（评述、口播稿、备注）不翻译，英文页只显示 frontmatter 字段。`checks` 里的 `claim`、`in_script` 保持中文原样。
